# Screenshot history

Back and Forward restore the screenshot named by a shared view URL even after a
different view was selected in the same page. Copying a view continues to use the
current screenshot, and existing fitted-image arrow navigation stays in place.

The browser history journey runs at desktop and phone widths in Chromium and
WebKit. Its scene fallback avoids a competing 3D renderer; the normal portfolio
journeys check the rendered car separately. Screenshot dimensions already reserve
image space while loading. Resume content is unchanged.

- [Desktop](preview-history-1440.png)
- [Phone](preview-history-390.png)

Browser viewport emulation does not establish physical-device gestures or native
assistive technology behavior.

The combined browser run exhausted the desktop Chromium journey’s deadline at its
final accessibility scan. That journey passed when run alone with the same deadline;
the other browser journeys passed in the combined run.
